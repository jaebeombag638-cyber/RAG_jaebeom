# 실습 프로젝트 작업과 학습 기록

## 현재 프로젝트부터 확인

- 사용자가 지정한 작업 폴더를 기준으로 현재 AGENTS.md, README, 대상 코드, 의존성 파일을 읽는다. 예전 프로젝트는 비교 자료로만 사용하고 수정 대상에 포함하지 않는다.
- 실행 환경·버전·모델·벡터 차원·서버 유무는 현재 파일과 실행 결과로 확인한다. 이전 실습의 Python 버전, BGE-M3, 1024차원, CPU 설정을 기본 사실로 옮기지 않는다.
- 기존 폴더 구조를 존중한다. 새 실습에서 구조가 없으면 코드 practice/, 설치 setup/, 설명 docs/ 정도의 단순한 구성을 고려한다.
- 가상환경·캐시·생성물은 일반 소스 탐색에서 제외한다. 환경 문제를 조사할 때만 필요한 부분을 읽는다.

## 설명 가능한 구현

- 한국어로 결과를 먼저 설명하고, 전문 용어는 처음에 짧게 풀이한다. 코드 설명은 실제 구현을 읽고 작성한다.
- 사용자가 한 줄씩 설명할 수 있도록 import의 목적, 함수의 입력·출력, 데이터 이동 순서, 주요 문법을 짧게 기록한다. 긴 설명은 작은 학습 단위로 나눈다.
- 현재 목적에 필요하지 않은 프레임워크·추상화·비동기 처리를 추가하지 않는다. 기존 타입 힌트와 입력 검증은 보존한다.
- 라이브러리, 모델 식별자, 디스크의 다운로드 파일, 실행 중 메모리를 구분한다. 비동기는 추론 가속이나 동시 요청 제어를 자동 보장하지 않는다.
- 모델 추론이 있다면 모델 재사용, 적절한 배치 처리, 입력 순서 보존을 검토한다. 경로는 코드나 프로젝트 기준으로 구성하고, 다른 프로젝트 캐시 재사용은 선택 설정과 기록으로 드러낸다.

## 실행과 근거

- Windows에서는 PowerShell과 UTF-8을 사용하고 프로젝트 가상환경 Python을 직접 실행한다. 활성화나 실행 정책 변경을 설치 절차의 필수 단계로 만들지 않는다. 다른 운영체제에서는 그 환경에 맞춘다.
- 동작·설치 변경에 맞춰 의존성과 설명을 갱신한다. 변경 범위에 맞는 검사만 수행한다. 문서만 바뀌면 모델 추론을 다시 실행할 필요가 없다.
- 임베딩을 수정했다면 실제 모델로 차원·개수·순서·유한값과 해당 설정의 정규화를 확인한다. 입력 검증을 수정했다면 빈 입력·공백·잘못된 타입을 확인한다.
- 데이터 전처리는 원본을 보존하고 형식·인코딩·식별자를 확인한다. 변경·제외·중복 처리의 기준과 개수를 기록하고 출처를 추적할 수 있게 한다.
- 코드 작성, 모의 테스트, 실제 서비스 검증, 최종 시연을 구분한다. 가짜 응답이나 준비 화면을 실제 검색·생성 결과로 설명하지 않는다.

## 학습 문서와 이어하기

- 학습 문서에는 목적, 파일 역할, 실행 명령, 핵심 코드 설명, 실제 검증 결과, 미완료 항목을 담는다. 사용자가 문서 하나로 공부하기를 원하면 코드 사본과 줄 번호를 포함하고 변경 시 동기화한다.
- 후속 작업 프롬프트가 필요하면 작업 폴더, 먼저 읽을 파일, 현재 상태 재확인, 실행 순서, 완료 기준, 증거 저장 위치, 필요한 사용자 입력을 명시한다.
- 후속 프롬프트를 작성하는 요청 자체를 외부 서비스 실행 지시로 해석하지 않는다. 키 입력·API 사용 보류 등 사용자 조건은 유지한다. 라이선스 변경·유료 작업·관리자 권한이 필요한 설치는 기존 승인 범위를 확인한다.
- 외부 환경 때문에 막히면 가능한 준비·진단까지 끝내고, 실제 오류와 다음에 필요한 조치만 기록한다. 중단된 전체 과제를 완료로 표시하지 않는다.

이 스킬은 공통 실습 방식이다. 개별 프로젝트의 경로·모델·서비스 설정은 해당 프로젝트 AGENTS.md와 학습 문서에 둔다.
